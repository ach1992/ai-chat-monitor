## Permissions

Current required permissions:

- `storage`
- `sidePanel`
- `notifications`
- `offscreen`
- `clipboardWrite`
Persistent ChatGPT host permissions remain:

- `https://chatgpt.com/*`
- `https://chat.openai.com/*`

Optional host envelope remains:

- `https://*/*`

The broad optional HTTPS envelope exists for exact runtime grants to user-configured OpenAI-compatible provider origins. It is not used to broaden normal ChatGPT monitoring.

Revision 10 does not require `webRequest`. A packaged MAIN-world content script is disabled by default and observes only a trusted user-initiated supported ChatGPT conversation `fetch` after that conversation is selected for monitoring, delegates that fetch unchanged, and consumes a cloned SSE response locally. It keeps only a bounded rolling in-memory tail needed to recognize a canonical terminal status or `data: [DONE]`; the full stream is not persisted or transferred by this observer.

Permission rationale is documented in `PRIVACY.md`, `docs/ARCHITECTURE.md`, `docs/CHROME_WEB_STORE_LISTING.md`, and `docs/REV10_PAGE_STREAM_TERMINAL.md` and must remain aligned with `src/manifest.json`.

## Validation and packaging gate

Required candidate commands:

```text
npm ci
npm run validate
npm run smoke:extension
npm run smoke:background
npm run package
```

CI must:

- check out and verify the exact candidate SHA;
- run typecheck, lint, and automated tests;
- load the actual unpacked extension in pinned Chrome for Testing and verify its service-worker identity;
- run hidden/background Chromium regressions;
- package the extension deterministically;
- verify ZIP layout and reject TypeScript/source-map/environment leakage;
- verify `build-info.json` source SHA;
- upload package/checksum/provenance artifacts.

Revision 9's strengthened browser regression additionally requires:

1. a same-endpoint `POST` returning non-SSE JSON must not acquire completion authority;
2. a hidden fresh assistant may change while no Stop control is present, but it must remain unresolved/`GENERATING` while the response is pending;
3. a verified SSE must remain open without any premature response notification;
4. only matching SSE completion can release hidden generation and permit response completion while the tab remains hidden;
5. exactly one user notification may be successfully delivered for the modeled response episode, even if non-delivered semantic diagnostics are retained in bounded history.
