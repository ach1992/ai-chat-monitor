# Chrome Web Store Readiness — v2.0.0

Status: **development candidate / not yet published**

This document tracks engineering and disclosure readiness for the v2 read-only monitoring release. Passing these checks does not itself authorize publication.

## Product contract

- [x] Single purpose is read-only monitoring/notification of selected ChatGPT conversations.
- [x] Manifest description matches monitoring-only behavior.
- [x] No product claim says Guardian automatically sends, retries, continues, or controls ChatGPT.
- [x] Optional status protocol is described as observational metadata only.
- [x] Legacy `_V1` status marker is compatibility input only.

## Runtime safety

Required before release:

- [ ] Exact candidate validation is green.
- [ ] Static/runtime regression coverage proves no ChatGPT composer write or conversation-control activation path exists.
- [ ] No in-chat self-check/bootstrap/recovery/continuation message is generated by Guardian.
- [ ] Known page blocker evidence outranks semantic/provider classification.
- [ ] Duplicate/background tabs do not duplicate one response episode's provider work/notification.
- [ ] Service-worker restart cannot restore v1 send authority.
- [ ] v1.2.5 policy migration produces monitoring-only state.

## Permissions

Current required permissions:

- `storage`
- `sidePanel`
- `notifications`
- `offscreen`
- `clipboardWrite`

Persistent ChatGPT host permissions:

- `https://chatgpt.com/*`
- `https://chat.openai.com/*`

Optional host envelope:

- `https://*/*`

Permission rationale is documented in `docs/CHROME_WEB_STORE_LISTING.md` and must stay aligned with `src/manifest.json`.

`offscreen` exists for optional local audio. `clipboardWrite` exists for explicit user-initiated copy buttons for status-protocol setup text; it does not paste into ChatGPT.

## Privacy and data transfer

- [x] Side Panel discloses that Guardian reads page state/bounded recent chat content for monitoring/classification.
- [x] Side Panel states that full transcripts are not stored.
- [x] Side Panel discloses optional provider transfer and secret redaction.
- [x] Side Panel discloses bounded Telegram metadata and read-only ChatGPT behavior.
- [x] `PRIVACY.md` describes provider/Telegram transfer, storage, clipboard, sound, and host-permission behavior.
- [x] Provider API keys and Telegram bot tokens remain in trusted extension storage.
- [x] Telegram is outbound-only and has no inbound remote-control path.
- [x] No developer-operated advertising/analytics/data-broker service is part of the product.

## Remote code

- [x] No remotely hosted executable code is intended.
- [ ] Exact candidate package scan is green for obvious remote-code patterns.

All extension JavaScript must be packaged locally. Optional provider and Telegram requests exchange data only.

## Packaging

Required candidate commands:

```text
npm ci
npm run validate
npm run smoke:extension
npm run package
```

CI must:

- check out the exact candidate SHA;
- verify the checkout identity;
- run validation and smoke checks;
- package the extension;
- verify the ZIP has `manifest.json` at its root;
- reject TypeScript/source-map/environment-file leakage;
- verify `build-info.json` points to the exact candidate SHA;
- upload the package/checksum/provenance artifacts.

Expected artifacts:

- `chat-turn-guardian-2.0.0.zip`
- `SHA256SUMS.txt`

## Release gate

A public v2.0.0 release is ready only when:

1. the exact candidate SHA is validated green;
2. the required review/integration gates pass;
3. the candidate is integrated into the intended release target;
4. a deterministic package/checksum/provenance set is produced from that identity;
5. the user explicitly approves publication/release where required.

Until then, any ZIP is a test candidate only.
